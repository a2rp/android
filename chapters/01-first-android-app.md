## What I am learning here

An Android app is more than a screen. The project contains Java source code, XML resources, a manifest, and build configuration. Android Studio uses Gradle to combine these pieces into an installable app. The Android system then starts the app's entry activity when it is launched.

In this first note, I connect a Java activity to an XML screen, display a message, and change that message when a button is tapped. This gives me a small example of how source code, a layout resource, and a user action work together.

## Create a Java and XML project

1. Open Android Studio and choose **New Project**.
2. Select a Views-based activity template, such as **Empty Views Activity**, when it is available. Confirm that the generated screen uses an XML layout.
3. Enter a project name such as `StudyApp` and choose a package name such as `com.example.studyapp`.
4. Select Java as the language if the template offers a language choice. Choose a minimum SDK suitable for the devices you want to support.
5. Finish creating the project and wait for Gradle sync to complete.

Template names and choices can differ between Android Studio versions. Before following the examples below, check that the project has a Java activity and a file such as `res/layout/activity_main.xml`. If the template created another activity name or layout name, use those names consistently or rename the files and references together.

## Find the first-screen files

In the Project view, the important files for this example are:

```text
app/
└── src/main/
    ├── AndroidManifest.xml
    ├── java/com/example/studyapp/MainActivity.java
    └── res/
        ├── layout/activity_main.xml
        └── values/strings.xml
```

The manifest describes app components to Android. The Java file contains the activity code. The layout file describes the screen's views, and the strings file stores text shown to the user. Android Studio may group these files differently in its Android view, but their paths are under the app module's `src/main` source set.

## Build a small screen in XML

Place this layout in `app/src/main/res/layout/activity_main.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:padding="24dp">

    <TextView
        android:id="@+id/message"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:text="@string/welcome_message"
        android:textSize="20sp" />

    <Button
        android:id="@+id/change_message"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginTop="16dp"
        android:text="@string/change_message" />

</LinearLayout>
```

`LinearLayout` arranges its children in a row or a column. Here, `vertical` places the message above the button. `match_parent` uses the available parent size, while `wrap_content` uses the size needed by the view. The IDs let Java find these views. `dp` is used for layout dimensions and spacing; `sp` is used for text so the user's font-size setting is respected.

Add the displayed text to `app/src/main/res/values/strings.xml`. Keep any other string entries already generated by the project.

```xml
<resources>
    <string name="app_name">StudyApp</string>
    <string name="welcome_message">Hello, Android!</string>
    <string name="change_message">Change message</string>
    <string name="updated_message">The button works.</string>
</resources>
```

The `@string/name` syntax points to a string resource. Keeping screen text in resources makes it easier to maintain and translate later.

## Connect the layout to Java

In `MainActivity.java`, replace the package name with the package used by your project. The `R` class is generated from resources during the build, so do not create or edit it manually.

```java
package com.example.studyapp;

import android.app.Activity;
import android.os.Bundle;
import android.view.View;
import android.widget.Button;
import android.widget.TextView;

public class MainActivity extends Activity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        TextView message = (TextView) findViewById(R.id.message);
        Button changeMessage = (Button) findViewById(R.id.change_message);

        changeMessage.setOnClickListener(new View.OnClickListener() {
            @Override
            public void onClick(View view) {
                message.setText(R.string.updated_message);
            }
        });
    }
}
```

`onCreate()` is called while the activity is being created. `setContentView()` attaches the XML layout to this activity. `findViewById()` returns the views whose IDs were declared in XML. The click listener runs its `onClick()` method after the user taps the button.

The cast on `findViewById()` keeps this example compatible with older Android API signatures. The ID must refer to the right view type: `message` is a `TextView`, and `change_message` is a `Button`.

## Check the launcher activity

Android reads `AndroidManifest.xml` to discover app components. A launcher activity has a `MAIN` action and a `LAUNCHER` category. The activity must also declare `android:exported` when it has an intent filter. Keep the manifest entries generated by Android Studio and check that the activity is declared only once. A minimal activity entry looks like this inside the existing `<application>` element:

```xml
<activity
    android:name=".MainActivity"
    android:exported="true">
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>
</activity>
```

If the generated manifest already contains this activity and filter, do not add a duplicate. The `.MainActivity` name is resolved relative to the app namespace configured for the module.

## Build and run

1. Let Android Studio finish syncing the project with Gradle.
2. Start an emulator from Device Manager, or connect an Android device with USB debugging enabled.
3. Select the app run configuration and the target device, then choose **Run**.
4. Wait for installation and launch. The screen should show **Hello, Android!**.
5. Tap **Change message**. The text should change to **The button works.**.

Android Studio delegates compilation and packaging to Gradle. A successful build confirms that the Java source, XML resources, manifest, and build configuration can be combined. The debug app is installed on the selected device so I can check its behavior.

## Common things to check

| Symptom | What to check |
| --- | --- |
| `R` or a resource ID is unresolved | Fix XML errors first, confirm the resource file name and ID, then run a build again. `R` is generated by the build. |
| The app opens but the screen is blank or different | Confirm that `setContentView()` uses the intended layout and that the edited XML file belongs to the app module. |
| `findViewById()` returns `null` | Check that the view is in the layout attached by `setContentView()` and that the ID spelling matches. |
| Android Studio cannot launch the activity | Check the manifest activity name and launcher intent filter. Do not declare the same activity twice. |
| The package line or `R` import does not match | Use the Java package and generated resource package configured by this project. The project structure notes explain the namespace in more detail. |

## Practice

Add a second button named `reset_message`. Give it a string resource named `reset_message`, then set the message view back to `@string/welcome_message` when it is tapped. Keep the view text in `strings.xml` and give the new button a unique ID.

When it works, I should be able to change the message and restore it without restarting the app.

## Notes to remember

- An activity is a screen entry point, and XML describes the views shown by that activity.
- `setContentView()` connects an activity to its layout resource.
- Resource IDs connect Java code to views declared in XML.
- The manifest tells Android which components belong to the app and which activity appears in the launcher.
- Gradle builds the source and resources into an app that can be installed and run.
